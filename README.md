# Yrys Kanban Platform 🚀
### Корпоративная система управления задачами с ролевым доступом (RBAC), канбан-досками и автоматическим машинным переводом

Проект разработан в точном соответствии с техническим заданием [tz.md](tz.md) с применением архитектурных паттернов **Clean Architecture**, **Domain-Driven Design (DDD)**, **Dependency Injection (DI)**, **Unit of Work (UoW)** на бэкенде и современного интерфейса на фронтенде (**Next.js 16**, **React 19**, **Tailwind CSS**, **SCSS**).

---

## 🏛️ Архитектура бэкенда (Clean Architecture + DDD + DI + UoW)

Проект бэкенда структурирован по строгим принципам чистой архитектуры:

```
backend/
├── domain/                               # СЛОЙ ДОМЕНА (Entities, Value Objects, Policies)
│   ├── entities.py                       # Доменные сущности: User, Board, Column, Card, Checklist, Comment, Attachment
│   ├── value_objects.py                  # Объекты-значения: RoleType, CardPriority, SupportedLanguage
│   ├── exceptions.py                     # Доменные исключения: PermissionDeniedException, EntityNotFoundException
│   └── services.py                       # Доменные сервисы: AccessPolicyService (проверка бизнес-правил ролей)
├── application/                          # СЛОЙ ПРИЛОЖЕНИЯ (Use Cases, DTOs, Interfaces)
│   ├── dtos.py                           # Входные и выходные DTO
│   ├── interfaces/
│   │   ├── uow.py                        # Интерфейс IUnitOfWork
│   │   ├── repositories.py               # Интерфейсы репозиториев (IUserRepository, IBoardRepository, ICardRepository)
│   │   └── services.py                   # Интерфейсы сервисов: ITranslationService, ITokenService, IReportService
│   └── use_cases/                        # Сценарии использования
│       ├── auth_use_cases.py             # Login, Profile, PasswordReset
│       ├── user_use_cases.py             # Управление пользователями (Admin)
│       ├── board_use_cases.py            # Управление досками (фильтрация по роли)
│       ├── column_use_cases.py           # Управление колонками и порядками
│       ├── card_use_cases.py             # CRUD задач, Drag & Drop перемещение
│       ├── checklist_use_cases.py        # Пункты чек-листов и отметки
│       ├── comment_use_cases.py          # Комментарии с автопереводом
│       ├── attachment_use_cases.py       # Файлы и вложения
│       ├── notification_use_cases.py     # Центр уведомлений
│       └── report_use_cases.py           # Аналитика и экспорт (Excel, Word, PDF)
├── infrastructure/                       # СЛОЙ ИНФРАСТРУКТУРЫ (ORM, DB, Внешние сервисы)
│   ├── persistence/                      # Django ORM & База данных
│   │   ├── models.py                     # Модели Django ORM
│   │   ├── mappers.py                    # Двунаправленные мапперы между ORM и Domain Entities
│   │   ├── repositories/                 # Реализации репозиториев
│   │   └── uow.py                        # DjangoUnitOfWork с транзакционностью transaction.atomic()
│   ├── services/
│   │   ├── jwt_service.py                # Генерация и валидация JWT токенов (PyJWT)
│   │   ├── translation_service.py        # Бесплатный машинный перевод + OpenCC (Упрощённый/Традиционный китайский)
│   │   └── report_service.py             # Генераторы Excel (openpyxl), Word (python-docx), PDF (reportlab)
│   └── di/
│       └── container.py                  # DI-контейнер (Service Locator / Composition Root)
├── presentation/                         # СЛОЙ ПРЕДСТАВЛЕНИЯ (REST API & Middleware)
│   ├── middlewares.py                    # JWT-аутентификация и валидация прав
│   ├── urls.py                           # RESTful маршруты API
│   └── api/                              # Контроллеры/Views: auth, users, boards, columns, cards, comments, reports
├── config/                               # Настройки Django (settings.py, urls.py, wsgi.py)
├── tests/                                # Юнит- и интеграционные тесты архитектуры
└── manage.py                             # Точка входа Django
```

## 🎨 Дизайн и UX/UI (Разработано как UX/UI дизайнером)

Интерфейс спроектирован по стандартам современных продуктовых SaaS-платформ (Linear, Notion, Trello, Craft):

1. **Цветовая палитра и типографика**:
   - Строгая нейтральная палитра (Slate/Zinc) с мягкими тенями, чистыми границами и размытием фона (`backdrop-blur`).
   - Четкие семантические акценты для приоритетов:
     - 🔴 **Срочный (Urgent)**: Rose / Ember с индикатором пульса.
     - 🟠 **Высокий (High)**: Amber / Vibrant Orange.
     - 🔵 **Средний (Medium)**: Ocean Blue.
     - ⚪ **Низкий (Low)**: Slate Teal.
2. **Эргономика канбан-доски**:
   - Горизонтальная прокрутка колонок с независимой вертикальной прокруткой карточек.
   - Плавное перемещение карточек методом **Drag & Drop** с сохранением порядка на сервере.
   - Счётчики задач в шапках колонок, индикаторы просроченных задач (Overdue), прогресс чек-листов (`2/3`).
   - Настраиваемые темы фона доски (Океан, Неон, Изумруд, Закат, Минимализм, Обсидиан).
3. **Многоязычность и автоматический перевод**:
   - 4 языка интерфейса: 🇷🇺 Русский (RU), 🇨🇳 Упрощённый китайский (zh-Hans), 🇭🇰 Традиционный китайский (zh-Hant), 🇰🇬 Кыргызча (KY).
   - Задачи, разделы и комментарии сохраняются сразу на трёх языках (RU, ZH, KY).
   - Конвертация китайского текста между упрощённой и традиционной графикой через OpenCC.
   - Кнопка **«Показать оригинал»** для задач и каждого комментария.
4. **Детальная карточка задачи**:
   - Вкладки многоязычного перевода (RU, ZH, KY).
   - Интерактивный чек-лист с прогресс-баром.
   - Вложения и загрузка файлов (счётчик со скрепкой).
   - Лента комментариев с автопереводом.
   - История изменений (Activity Log) с указанием времени и автора.
5. **Отчёты и аналитика (для Генерального директора)**:
   - Сводные KPI-карточки (Всего, Выполнено, В процессе, Просрочено, Баги, Успешность %).
   - Сравнение отделов и прогресс-бары завершения.
   - Таблица эффективности сотрудников (задачи, среднее время выполнения, конверсия).
   - **Мгновенная выгрузка отчётов**:
     - 📥 **Excel (.xlsx)** с форматированными шапками и границами (openpyxl).
     - 📥 **Word (.docx)** с оформленными таблицами и показателями (python-docx).
     - 📥 **PDF (.pdf)** с версткой документа (reportlab).
6. **Администрирование**:
   - **Управление отделами**: создание, редактирование, просмотр сотрудников и досок отдела.
   - **Управление пользователями**: создание, роли, отделы, привязка к 1 доске, блокировка, сброс пароля.
   - **Управление досками**: привязка к отделу, назначение руководителя и сотрудников, шаблоны разделов.
   - **Матрица прав**: интерактивная матрица ролевого доступа (RBAC).
   - **Django Jazzmin Admin**: современная и комфортная административная панель с инлайнами и фильтрацией.

## 🔐 Разграничение ролей и безопасность (RBAC)

| Роль | Доступ к доскам | Разделы (Колонки) | Карточки (Задачи) | Перемещение | Комментарии | Отчёты и Админка |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **👑 Генеральный директор** | **Все доски** всех отделов | Полный CRUD | Полный CRUD | Разрешено | Разрешено | **Полный доступ** + Экспорт |
| **👨‍💼 Руководитель** | **Только 1 доска** своего отдела | Полный CRUD на своей | Полный CRUD на своей | Разрешено | Разрешено | Запрещено (403) |
| **💻 Сотрудник** | **Только 1 доска** привязанная админом | Запрещено (403) | Запрещено (403) | Разрешено | Разрешено | Запрещено (403) |

*Каждый запрос проверяется доменной политикой `AccessPolicyService` на сервере: обращение к чужой доске возвращает ошибку 403 Forbidden даже при прямом переходе по ссылке.*

## ⚡ Быстрый запуск

Перед первым локальным запуском скопируйте `.env.example` в `.env` в корне
репозитория. Сгенерируйте отдельный ключ командой ниже и запишите результат
в `DJANGO_SECRET_KEY` в `.env` (не публикуйте его):

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Для локальной разработки оставьте `DJANGO_DEBUG=True`. Django читает только
корневой `.env` независимо от текущего каталога; уже заданные переменные
окружения имеют приоритет. `.env` не добавляется в Git. В production задайте
`DJANGO_DEBUG=False` и постоянный уникальный `DJANGO_SECRET_KEY` через окружение
развёртывания: без ключа запуск завершится ошибкой.

Проверка конфигурации без изменения базы данных:

```bash
backend/venv/bin/python backend/manage.py check
```

### Вариант 1. Универсальный скрипт запуска
```bash
./run.sh
```

### Вариант 2. Запуск вручную

**1. Бэкенд:**
```bash
backend/venv/bin/python backend/manage.py migrate
backend/venv/bin/python backend/seed_data.py
backend/venv/bin/python backend/manage.py runserver 127.0.0.1:8080
```

**2. Фронтенд:**
```bash
cd frontend
npm run build
npx next start -p 3001
```

- **Frontend URL:** [http://localhost:3001](http://localhost:3001)
- **Backend API:** [http://127.0.0.1:8080/api](http://127.0.0.1:8080/api)
- **Django Jazzmin Admin:** [http://127.0.0.1:8080/admin/](http://127.0.0.1:8080/admin/) (Вход: `director@company.com` / `password123`)
