# OA/ERP — правила команды ИИ

Перед работой прочитать [общие инструкции](ai/GLOBAL_INSTRUCTIONS.md) и описание
своей роли из [каталога](ai/agents.json). Это единые проектные правила для Codex,
Claude Code и других ассистентов; ограничения самой среды остаются в силе.
Статус и решения сообщать по-русски.

## Команда

| ID | Роль | Имя Codex | Канонические инструкции |
| --- | --- | --- | --- |
| TL-01 | Руководитель проекта | `tech_lead_project_manager` | `ai/agents/tech-lead.md` |
| BE-01 | Backend-архитектор/разработчик | `backend_architect_developer` | `ai/agents/backend-architect.md` |
| FE-01 | Frontend-разработчик | `frontend_developer` | `ai/agents/frontend-developer.md` |
| UX-01 | UI/UX-дизайнер | `ui_ux_designer` | `ai/agents/ui-ux-designer.md` |
| CR-01 | Независимый reviewer | `senior_code_reviewer` | `ai/agents/senior-code-reviewer.md` |

Ведущий ассистент выполняет TL-01. Назначать независимые части профильным агентам
с явным ownership файлов/сервисов; UX handoff предшествует существенному UI,
BE-01 согласует модульные границы и API до реализации, CR-01 отдельно проверяет
actual diff. Один файл — один активный владелец. Сохранять пользовательские правки.

Текущий этап — модульный монолит на существующем Django backend согласно ТЗ.
Микросервисы отложены и не блокируют функциональные задачи. Действующее решение:
`docs/adr/0002-monolith-for-current-delivery.md`; прежний ADR-0001 заменён.
Не мигрировать систему молча и не принимать «Согласовать» за утверждение.

Не делать commit/push/deploy, удаление данных или изменения внешних сервисов
без разрешения. После завершения части объяснить её работу, проверки и
ограничения; спросить о следующей задаче и ждать ответа пользователя.

Адаптеры: `.codex/agents/*.toml`, `.claude/agents/*.md`. Править источники в `ai/`,
затем запускать `python scripts/sync_ai_agents.py`; проверка — с `--check`.
Использование и переносимость: `ai/README.md`.
