# Проверка заявок на оплату

Дата31.10.2026. Модульный монолит. Контракт/API и ADR0007 фиксируют текущую
границу: настроенный последовательный маршрут, отдельная регистрация платежа,
одна утверждённая заявка — один точный платёж. Пороговые/параллельные маршруты,
полный налоговый учёт и выполнение всего ТЗ этим этапом не заявляются.

## Поведение и безопасность

Заявка сохраняет долг, счёт, точную сумму/валюту, плановую дату, назначение.
Редактировать/отправить/отменить может автор с finance.payment.manage;
регистрация платежа и доказательства доступны разрешённому финансовому исполнителю.
Согласующий назначается сохранённым маршрутом, не является автором; директор
не обходит назначение и запрет самосогласования. Отсутствие настройки блокирует
отправку. Возврат требует причины, исправления требуют нового снимка.

Платёж сверяет утверждённый снимок, активный счёт, остаток долга/банка,
валюту, приватный загруженный proof_id и открытый период. Всё записывается
атомарно с аудитом IP/old/new. Точный повтор возвращает прежний платёж, включая
после закрытия периода. Новый ключ/заявка не считается повтором старой операции.

Файлы приватные: PDF до15MiB с проверкой header/end (не антивирусная сертификация),
JPEG/PNG/WebP до10MiB/20MP с декодированием и повторным сохранением без метаданных,
до5активных. Удаление логическое. Согласующий видит только proof из его snapshot,
не новые файлы исправленной заявки; финансы — по текущим правам. Оплаченные
доказательства неизменяемы. Protecteddownload Bearer,no-store,nosniff.

## Браузерные проверки

Playwright+axe на mock API:16сочетаний RU/KY/zh-Hans/zh-Hant × светлая/тёмная
тема × ширина360/1440. Реальный multipartPNG, защищённое скачивание с Bearer,
платёж summary→confirm, правильное уменьшение долга/банка. JS/overflow/axe
нарушений в проверенных состояниях не найдено. Ещё сценарий потерянного ответа:
точный повтор payload даёт один платёж и одно списание. JSON17строк:
`/tmp/yrys-payment-check/results.json`.

Центр согласований: отдельно2сценария на360px — чтение финансового снимка
и подтверждение этапа, read-only snapshot без действий. JSON:
`/tmp/yrys-payment-check/approvals.json`. Мобильный переход добавлен в Navbar.
До этого повтор проходил только desktop→resize; итоговые2сценария открываются
из мобильной навигации. Это mock-проверки, не реальный Django/PostgreSQL E2E
и не полная сертификацияWCAG.

Frontend на3018, PlaywrightChromium/axe-core во внешнем окружении, из корня:

## Внедрение и ограничения

Миграция0051 подготовлена, рабочая БД не менялась. Исторические платежи получают
nullablelink, фиктивные согласования не создаются. Breakingchange: новыйPOST
платежа без payment_request_id/утверждения/proof_id отклоняется. Интеграциям
нужно перейти на новый контракт; миграция сама старые клиенты не исправляет.
Файл+DB не образуют общую транзакцию; неудача записи метаданных/аудита удаляет
сохранённый файл, аварийные orphanfiles требуют эксплуатационной сверки.

Незавершённые UUIDcreate/подписьплатежа хранятся только в памяти вкладки с
привязкой к сессии. Полная перезагрузка теряет их: перед новой операцией нужно
сверить историю. Нет выдачи persistentbrowserstorage за exactlyonce.
Реальные PostgreSQL contentionтесты пропускаются наSQLite и не объявляются
успешно выполненными. Commit/push/deploy/рабочие миграции не выполнялись.

Финальные targeted:12тестов49.903с `OK(skipped=2)`; две PostgreSQL-гонки
не выполнялись наSQLite. Исправленные старые тесты2/5.805с `OK`.
Первый широкий37тестовый прогон выявил ошибки типов фабрики; Decimal-исправление
проверено обоими ранее упавшими сценариями. API/production-проверки не обходились.
Frontend8файлов:lint/TypeScript/build exit0 безпредупреждений; check/migrationdryrun/
OpenAPI/diffcheckуспешны. Browser17+2mockсценария прошли.

Финальный полный backend-прогон: **169тестов**,268.692с, `OK(skipped=10)`.
159выполнены; десять PostgreSQL-проверок конкурентности пропущены наSQLite.

не подтверждаются данным этапом.
