# Возврат поставщику: проверка этапа

## Выполненные проверки

- Полный backend: `/tmp/yrys-ci-python312/bin/python manage.py test` из backend
  с тестовыми настройками окружения: 131 тест, `OK (skipped=5)`, 188.886 с.
  Пять PostgreSQL concurrency-тестов пропущены на SQLite; блокировки PostgreSQL
  этим прогоном не подтверждены. Рабочая база не использовалась.
- Отдельные supplier return тесты: 18, `OK (skipped=2)`; покрыты права,
  независимое согласование, источники/лимиты, партии, фотографии, идемпотентность,
  откат транзакции и неизменность денежных данных.
- OpenAPI: `python -m openapi_spec_validator docs/openapi/supplier-returns.json`.
- Frontend: `npm run lint`, `npx tsc --noEmit`, `npm run build`.
- Браузер: 32 сочетания двух ролей (складской согласующий/финансы), четырёх
  языков, двух тем и ширины 360/1440. Открытие документа/финансовой записи,
  защищённое фото с Bearer; ошибок JS, переполнения и найденных axe-нарушений нет.

## Воспроизведение браузерной проверки

Запустить frontend на порту 3015, установить Playwright Chromium и axe-core
во внешнем проверочном окружении, затем:

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright \
AXE_MODULE=/path/to/node_modules/axe-core/axe.min.js \
node docs/verification/supplier-returns-smoke.cjs
```

Сценарий использует mock API, не реальный Django/PostgreSQL. Это проверка
отрисовки и приватных запросов, не полноценная E2E-приёмка маршрута возврата,
не проверка всех async-состояний и не сертификация WCAG. Результаты и снимки
сохраняются в `/tmp/yrys-returns-check`.

## Граница готовности

Миграция 0048 подготовлена, к рабочей БД не применена. Складское проведение
создаёт pending-запись финансового рассмотрения. Бухгалтерская корректировка,
уменьшение долга и возврат денег не реализованы этим этапом: правила и
валюта оценки остаются открытыми в ADR-0004. Полное выполнение ТЗ не заявляется.

Независимое ревью CR-01: **APPROVED** для складского возврата и очереди pending;
открытых обязательных замечаний нет. Бухгалтерская корректировка не принята.
