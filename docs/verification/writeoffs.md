# Браузерная проверка списаний

Установить инструменты и запустить frontend, как описано в `warehouse.md`.
Из корня проекта выполнить:

```bash
export PLAYWRIGHT_MODULE=/tmp/yrys-ui-check/node_modules/playwright
export AXE_MODULE=/tmp/yrys-ui-check/node_modules/axe-core/axe.min.js
node docs/verification/writeoffs-smoke.cjs
node docs/verification/writeoffs-flows.cjs
node docs/verification/writeoffs-async.cjs
```

Адрес frontend по умолчанию — `http://127.0.0.1:3015`; другой задаётся через
`UI_BASE_URL`. Все API-ответы, изображения и пользователи тестовые: никакие
документы и фотографии не загружаются в рабочий backend.

Результаты 31.10.2026:

- Матрица: четыре языка, две темы и 360/1440 px; детали с приватным превью
  и действиями согласующего. После исправления навигации все 16 сочетаний
  прошли без ошибок JS, переполнения и найденных axe WCAG 2 A/AA, 2.1 AA
  нарушений. JSON/скриншоты: `/tmp/yrys-writeoff-check`.
- Основной маршрут: 10 запросов изменения, включая неуспешную загрузку
  с последующим повтором, удаление из черновика и независимое согласование — PASS.
- Проверена передача реальных PNG-байтов через multipart, bearer в запросах
  приватного изображения и скачивание через Blob URL вместо публичного пути.
- Async: шесть сценариев задержек/отмены/отзыва доступа и точного открытия
  из движений, включая React StrictMode и повтор после 500 — PASS.
- Полный backend: 104 теста, `OK (skipped=3)` на SQLite.

Матрица не заменяет ручную проверку доступности. Mock API не подтверждает
интеграцию с рабочей БД: серверные проверки выполняются Django-тестами,
а реальная конкурентность требует PostgreSQL.
