# ADR-0006: закрытие финансового месяца

Статус: технический контракт согласован TL-01; карта дат явно подтверждена пользователем.
Основание: ТЗ Г.6 и критерий закрытого периода, ADR-0002 модульный монолит.

## Решение

Использовать существующий FinancePeriod(year,month,is_closed), добавить причину
закрытия, ограничения года/месяца, новое явное finance.period.close без назначения
ролям. Чтение — существующее finance.payable.read либо право закрытия. Закрытие
необратимо через API, сохраняет автора/время/причину и аудит атомарно; повтор
не изменяет доказательства. Нет выдуманных порогов/нулевого баланса/закрытия всех
заявок как предусловия. Интерфейс предупреждает о замораживании документов.

## Блокировки вместо проверок exists

Общий require_open_period берет select_for_update().get_or_create() строки
месяца. Все денежные writers и закрытие удерживают одну строку до commit.
Блокировка отдельного документа без месяца не защищает гонку закрытия.
Брокер/outbox не нужен: всё в одной БД. Наборы месяцев блокируются в одном
хронологическом порядке. Закрытие не берёт document/payable locks, чтобы не
создавать обратный порядок блокировок. Ошибка откатывает документ и аудит.

## Даты и исторические документы

Деловая дата автоматической выплаты определяется Asia/Bishkek, timestamps UTC
и глобальные настройки проекта не меняются. Новая операция в открытом месяце
не переписывает сумму/дату закрытого источника; меняется только проекция
погашения из отдельных документов. Карта дат подтверждена пользователем и приведена ниже. Возврат денег/FX/план счетов не вводятся этим решением.

## Внедрение

0050 добавляет метаданные и ограничения; существующие некорректные year/month
нужно исправлять явно по отдельному плану, миграция их молча не переписывает.
Миграция рабочей БД не запускалась. Прямые financial admin writes должны быть
отключены; просмотр сохраняется. Существующие файлы и отчёты не удаляются.
PostgreSQL contention-тесты нужны отдельно, SQLite skip не является проверкой.


## Подтверждённая карта защиты

| Запись | Месяц защиты |
| --- | --- |
| Создание/изменение/отправка/решение/вложение расхода | purchase_date |
| Создание и подтверждение сверки поставщика | period_end (не все месяцы диапазона) |
| Начисление зарплаты | year/month расчёта |
| Платёж поставщику | payment_date нового платежа |
| Возмещение сотруднику | дата paid_at в Asia/Bishkek, время фиксируется однократно |
| Документ корректировки долга | posting_date нового документа |

Новая оплата/корректировка в открытом месяце может погасить старую задолженность;
сумма, дата и источник закрытого документа не меняются. Статусы и остатки погашения
— проекция новых отдельных платежей/корректировок. Исторические GET/экспорт/скачивание
остаются доступны по прежним правам. Прямые add/change/delete финансовых записей
в Django admin запрещены, просмотр сохраняется. Корректировка старого расхода
или зарплаты не реализована — закрытый источник нельзя переписать.

Все операции перечисленных API используют общий row lock периода и транзакцию
документа/аудита. Закрытый месяц возвращает409 `period_closed` без частичных
изменений. Точный повтор уже проведённой UUID-корректировки возвращает прежний
документ даже после закрытия, не является новой записью и не требует открытия.
