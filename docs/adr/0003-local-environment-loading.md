# ADR-0003: явная загрузка локальной конфигурации Django

Дата: 31.10.2026.
Статус: принято для исправления локального запуска; независимое ревью — APPROVED.

## Контекст

Зависимость python-dotenv установлена, но Django не читает `.env`. При отсутствии
переменных окружения `manage.py check` корректно отклоняет запуск без production
ключа. Копирование старого примера ключа не обеспечивает секретность.

## Решение

Модуль `backend.config.settings` загружает только `.env` из корня репозитория,
вычисленного относительно самого файла настроек. `override=False` сохраняет
приоритет уже заданного окружения, включая `DJANGO_DEBUG=False` и пустой ключ.
Одинаковое поведение применяется к manage.py, WSGI и ASGI, независимо от cwd.
Файл необязателен; автоматического поиска родительских `.env` нет.

Альтернативы: shell export не требует загрузчика, но расходится с имеющимся
примером `.env`; загрузка только в manage.py оставляет WSGI/ASGI с другим
поведением. Выбрана общая точка настройки с уже установленной зависимостью.

## Ограничения и проверка

Production по-прежнему требует явно настроенный уникальный ключ и отклоняет
известный прежний пример. Debug не включается кодом автоматически. Существующее
исключение для Django test runner не меняется. Локальный `.env` исключён из Git;
реальные значения не входят в patch. В production конфигурация задаётся окружением
развёртывания. Внешние API, события, схема БД и архитектура монолита не меняются;
миграций и действий с данными нет. Откат — удалить загрузку `.env` и задавать
переменные окружения явно. Subprocess-тесты изолируют окружение и файлы настроек.

CI задаёт общий временный случайный ключ через GITHUB_ENV до check и тестов;
ключ маскируется и не хранится в workflow. Локальная проверка CI shell-блока
и девять изолированных регрессионных тестов прошли. Удалённый CI не запускался.
