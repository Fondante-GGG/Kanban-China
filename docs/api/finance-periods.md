# Финансовые периоды

Модуль финансов монолита; решение и границы: [ADR-0006](../adr/0006-finance-period-closure.md).

GET `/api/finance/periods?year=YYYY`: чтение `finance.payable.read` либо
`finance.period.close`. Ответ `{year,items,can_close}`; items всегда12 месяцев,
включая виртуальные открытые, без создания строк при GET. Месяц:
`{year,month,is_closed,closed_by_name,closed_at,close_reason}`. Неизвестные автор
и время — null; причина — пустая строка. Year строго четырёхзначный0001..9999.

POST `/api/finance/periods/{year}/{month}/close`: `finance.period.close`, JSON
`{"reason":"Проверка месяца завершена"}`. Только reason, непустая строка до4000
символов без NUL. Year1..9999,month1..12.200 возвращает DTO одного месяца.
Повторное закрытие — no-op, исходные автор/время/причина сохраняются, второй
аудит не создаётся. UUID не требуется для монотонного перехода ресурса.
Нет повторного открытия, удаления и прямого редактирования периода.

Ошибки:400 `invalid_input`,403 `permission_denied`,405 `method_not_allowed`;
неверный JSON — существующая domain400. Все ответы успеха `private,no-store`.
Закрытие и аудит атомарны; ошибка аудита не оставляет закрытый период.
Новый grant не назначается ролям автоматически, сохраняется существующее
проектное поведение general_director с ALL_PERMISSIONS.

Проверка открытого периода и закрытие берут одну row lock в той же локальной
транзакции, что и изменения денежных данных. Конкурирующая операция либо
завершается перед закрытием, либо получает409 `period_closed`. SQLite не
доказывает эту гарантию PostgreSQL. Миграция0050 подготовлена, не применена.

Даты исходных документов и допустимые текущие выплаты по старым долгам
подтверждены пользователем и описаны ниже и в ADR. Закрытие — блокировка
записи месяца, не автоматическая бухгалтерская отчётность/налоговый расчёт.


## Подтверждённая карта защиты

| Запись | Месяц защиты |
| --- | --- |
| Создание/изменение/отправка/решение/вложение расхода | purchase_date |
| Создание и подтверждение сверки поставщика | period_end (не все месяцы диапазона) |
| Начисление зарплаты | year/month расчёта |
| Платёж поставщику | payment_date нового платежа |
| Возмещение сотруднику | дата paid_at в Asia/Bishkek, время фиксируется однократно |
| Документ корректировки долга | posting_date нового документа |

Новая оплата/корректировка в открытом месяце может погасить старую задолженность;
сумма, дата и источник закрытого документа не меняются. Статусы и остатки погашения
— проекция новых отдельных платежей/корректировок. Исторические GET/экспорт/скачивание
остаются доступны по прежним правам. Прямые add/change/delete финансовых записей
в Django admin запрещены, просмотр сохраняется. Корректировка старого расхода
или зарплаты не реализована — закрытый источник нельзя переписать.

Все операции перечисленных API используют общий row lock периода и транзакцию
документа/аудита. Закрытый месяц возвращает409 `period_closed` без частичных
изменений. Точный повтор уже проведённой UUID-корректировки возвращает прежний
документ даже после закрытия, не является новой записью и не требует открытия.
