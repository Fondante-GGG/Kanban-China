# KPI API: текущий контракт

Все адреса имеют префикс `/api`, требуют Bearer-аутентификацию. Для чтения и действий сотрудника требуется `kpi.read` либо `kpi.manage`; для назначения, шаблонов, оценки руководителя, проверки и архива — `kpi.manage`.

## Данные и полномочия

- Генеральный директор видит все оценки и активных сотрудников для назначения.
- Руководитель видит оценки и кандидатов своего отдела. Руководитель без отдела не получает доступ к сотрудникам без отдела.
- Остальные пользователи с доступом к KPI видят только свои оценки. Они могут отправлять самооценку и подтверждать ознакомление.
- Оценивать руководителем и назначать могут директор и руководитель своего отдела с `kpi.manage`. Разрешение модуля само по себе не открывает чужие данные.
- Вышестоящую проверку выполняет генеральный директор; он не может проверять свою оценку или оценку, которую сам выставил как руководитель. При одном директоре, выступившем оценивающим руководителем, потребуется другой директор для независимого утверждения. Отдельная конфигурируемая иерархия проверяющих пока не реализована.
- `allowed_actions` в каждой оценке отражает действующие серверные полномочия: `self_score`, `manager_score`, `review`, `acknowledge`, `archive`. Отозванный доступ закрывает прямые запросы записи.

## Методы

### `GET /kpi/templates`

Ответ `{items:[{id,name,position_code,cycle,is_active,items:[{id,name_ru,name_zh,name_ky,weight,formula}]}]}`. Шаблоны общие, оценки сотрудников через этот метод не выдаются.

### `POST /kpi/templates`

Тело `{name,position_code,cycle,items:[{name_ru,name_zh?,name_ky?,weight,formula?}]}`. Периодичность `month`, `quarter` или `year`; от 1 до 100 показателей, каждый вес положительный, сумма весов ровно 100. Имена и коды ограничены длиной полей модели. Создание шаблона и показателей атомарно. Ответ `201 {id}`.

`formula` допускает только пустую строку либо `manual`: произвольные выражения не исполняются и не принимаются. Значения весов и баллов конечные, не более двух знаков после запятой. Создание записывается в аудит как `kpi.template_created` с автором, IP и метаданными шаблона/показателей; отказ аудита откатывает шаблон и показатели.

### `GET /kpi/assignees`

Для назначения без доступа к HR-реестру. Ответ `{items:[{id,full_name_ru,full_name_zh,full_name_ky,position,department_id}]}`; `id` — идентификатор сотрудника. Только активные сотрудники с активной связанной учётной записью в разрешённом объёме данных. Паспорт, зарплата и контакты не возвращаются.

### `GET /kpi/tasks`

Фильтры: `archived=true|false` (по умолчанию `false`), `status`, `year`. Пагинация `limit=1..100` (по умолчанию 100), `offset>=0`. Ответ `{items:[task],count}`; `count` учитывает фильтры до пагинации.

Оценка содержит:

- `id,employee_id,template_id,year,period,status`;
- `employee_name_ru,employee_name_zh,employee_name_ky,template_name,position_code,cycle`;
- `self_score,manager_score,final_score` — decimal-строки либо `null`;
- `acknowledged_at,reviewed_at,archived_at` — ISO timestamp либо `null`;
- `manager_scored_by_id,reviewed_by_id`;
- `comments:{self?:{ru,zh,ky},manager?:{ru,zh,ky},review?:{ru,zh,ky}}`;
- `allowed_actions`;
- `history:[{id,action,actor_name,created_at,old_data,new_data}]` — журнал только этой доступной оценки. Возвраты сохраняются в журнале, даже если текущий комментарий позже заменён.

### `POST /kpi/tasks`

Тело `{template_id,employee_id,year,period}`. Шаблон должен быть активным, сотрудник — доступным для назначения. `year` от 2000 до 9999. `period`: для месяца `01`…`12`, квартала `1`…`4`, года `year`. Повтор комбинации шаблон/сотрудник/год/период возвращает 409. Ответ `201 {id,status:"self_review"}`.

### `POST /kpi/tasks/{id}/score`

Тело `{stage:"self"|"manager",score,comment_ru?,comment_zh?,comment_ky?}`. Балл от 0 до 100, комментарий до 4000 символов на язык.

- Самооценка владельцем: `self_review -> manager_review`.
- Оценка руководителем (кроме самого оцениваемого): `manager_review -> senior_review`. На этом этапе окончательный балл ещё не утверждён.

Ответ `200 {id,status}`. Все переходы и записи аудита транзакционные, строка оценки блокируется до завершения операции.

### `POST /kpi/tasks/{id}/review`

Тело `{decision:"approve"|"return",comment_ru?,comment_zh?,comment_ky?}`. Доступен независимому директору только из `senior_review`.

- `approve`: `confirmed`, финальный балл равен баллу руководителя, сохраняются проверяющий и время.
- `return`: `manager_review`, нужен непустой комментарий хотя бы на одном языке; окончательного балла нет.

Ответ `200 {id,status}`.

### `POST /kpi/tasks/{id}/acknowledge`

Без тела, только сотрудник-владелец с доступом к KPI, только `confirmed`. Ответ `200 {id,status,acknowledged_at}`. Статус остаётся `confirmed`; повтор возвращает исходное время без повторной записи аудита.

### `POST /kpi/tasks/{id}/archive`

Без тела, доступное руководителю/директору завершённое `confirmed` с ознакомлением. Ответ `200 {id,status,archived_at}`. Повтор идемпотентен. Архивная оценка остаётся доступной через фильтр и не имеет действий изменения.

## Ошибки

Ошибки методов KPI имеют тело `{error,code}`: `validation_error` (400), `permission_denied` (403), `not_found` (404), `invalid_transition` (409), `duplicate_task` (409), `method_not_allowed` (405). Ошибки аутентификации обрабатываются общим middleware (401). Недопустимый переход score возвращает 403. Неизвестное значение stage возвращает 400.

## Миграция и совместимость

Миграция `0045_kpi_review_archive` добавляет nullable поля проверяющего, времени и архива, JSON-комментарии и расширяет значения cycle/status. Существующие `confirmed` оценки не переводятся назад и могут быть подтверждены сотрудником прежним способом. `acknowledged_at` из миграции 0044 сохраняется.

**Изменение контракта:** новая оценка руководителя теперь переводит в `senior_review`, а не сразу в `confirmed`. Клиент должен отображать отдельное независимое утверждение. Миграция не применялась к рабочей базе в ходе реализации; требуется штатный rollout вместе с обновлённым frontend.

## Оставшийся объём Г.8

Этот этап реализует ручной общий балл, шаблоны с весами, маршрут, журнал и архив. Баллы по каждому показателю, автоматические метрики из других модулей, настраиваемые безопасные формулы, обновление шаблона при переводе и передача результатов в расчёт премий ещё не реализованы. Вес показателей сейчас служит описанию шаблона, автоматического взвешенного расчёта нет.

Реальный тест конкурентных запросов использует `select_for_update` и требует PostgreSQL. На SQLite такой тест пропускается: SQLite не обеспечивает те же блокировки строк.
