# Online WMS: handoff

Дата: 31.10.2026. Источники: Б7.7/Г.7 объединённого ТЗ; текущие складские
модели и `procurement_views.py`; визуальные правила `KpiView.tsx`.
Владелец handoff — Designer, реализация — Frontend Developer.

## Цель и границы

Кладовщик работает с назначенным складом: проверяет остатки по ячейкам,
находит движение и его первичный документ, создаёт приход по заказу и отдельно
проводит его; фиксирует факт инвентаризации и отдельно утверждает расхождения.
Сервер определяет доступные склады и действия. Нельзя выбирать склад или
первичный документ вводом произвольного ID.

Этот этап — online WMS. Полные перемещения с отдельными отправкой/получением,
возвраты, списания с фото, PDA/offline, автоматические уведомления и обработка
просрочки остаются за его пределами. Не показывать работающие кнопки для этих
процессов. Старое прямое проведение перемещения не выдавать за требуемый ТЗ
маршрут. Инвентаризационная модель пока не хранит ячейку: явно подписать
ограничение «Только остатки без ячейки», не называть его пересчётом всего склада.
Корректировка остатков с партиями этим маршрутом также не поддерживается:
при серверном отказе показать понятное объяснение, а не предлагать обход.
Согласовано с Backend: себестоимость приёмки при пропущенном поле берётся из
заказа; override возможен только с `warehouse.cost.read`. Каталог заказов для
пользователей кроме директора ограничен своим отделом; цены каталог не раскрывает.

## Навигация и иерархия

Новый раздел «Склад» в desktop/mobile навигации при наличии хотя бы одного
складского права. `h1`, краткое описание, справа «Обновить». Ниже обязательный
выбор доступного склада (при единственном допустимо выбрать его автоматически).
У пустого списка складов — объяснение отсутствия назначения без форм мутаций.

Представления — обычные кнопки с `aria-pressed`, не ARIA tabs:
«Остатки», «Движения», «Приёмки», «Инвентаризации», «Сроки годности».
Показывать только представления с соответствующим серверным разрешением.
Фильтр склада общий; локальные фильтры сбрасывают пагинацию.

Остатки: SKU/название, склад, ячейка («Без ячейки» для null), физическое
количество, партии/сроки, себестоимость только если поле присутствует в ответе.
Нельзя предоставлять inline edit количества. Пустое поле стоимости не заменять
нулём: скрыть колонку целиком при отсутствии права. Поиск SKU и выбор ячейки —
только при поддержке контрактом.

Движения: дата, SKU, ячейка, тип, изменение количества со знаком, причина,
первичный документ (тип + номер, не один ID). «Открыть документ» переводит
к соответствующей приёмке/инвентаризации в этом разделе, фокусирует заголовок.
Если первичный тип пока не представлен экраном, показать идентификатор как
текст без ложной ссылки. Не обещать детализацию источника без endpoint.

Приёмки: номер, заказ, склад, статус, дата, кнопка «Открыть».
Детали inline: строки с заказано/ранее принято/принимаем, SKU, ячейка,
партия и срок, причина расхождения; комментарий документа. Отдельная кнопка
«Провести приёмку» с пояснением о создании неизменяемых движений. После успеха
обновить документ и остатки; повторное действие не оставлять доступным.

Инвентаризации: номер, склад, статус, дата и детали строк:
SKU, учётный остаток на момент фиксации, фактический остаток, разница, причина.
Сохранение факта не меняет остатки. «Утвердить расхождения» отдельно и только
по `allowed_actions`. При изменившемся учётном остатке — локализованный конфликт
и инструкция обновить данные/создать актуальный пересчёт, без потери введённого
текста и без принудительного обхода серверного отказа.

Сроки: выбор горизонта 1–365 дней, список партий по возрастанию срока,
SKU, ячейка, количество, дата, явный статус «Просрочено»/«Скоро истекает».
Просроченные партии не скрывать. Сертификаты показывать отдельным списком,
только если сервер возвращает их в разрешённом scope. Не предлагать
«Списать»/«Вернуть» без документного маршрута.

## Формы

Длинные формы inline на странице. Новая приёмка: номер, заказ из разрешённого
списка, склад, комментарий; динамические строки заказа, целое положительное
количество, ячейка текущего склада, партия и срок годности парой, причина
расхождения при отличии от ожидаемого. Не давать пользовательский ввод закупочной
цены без права стоимости; итоговое поведение поля определяется согласованным API
(серверная цена из заказа предпочтительна). Не подставлять выдуманный ноль.

Новая инвентаризация: номер, склад, строки активных SKU с фактом >=0,
до трёх десятичных знаков по контракту, причина для ненулевого расхождения.
Указать ограничение остатков без ячейки рядом с формой и в деталях.
Динамические строки — `fieldset/legend` с номером; удалить строку можно при
минимуме одной. Запрещены повторные SKU/строки заказа согласно API.

У каждого control постоянный label; обязательность помечена текстом/required.
Ошибки рядом с полем через `aria-invalid`, `aria-describedby`; общая ошибка
`role=alert`. После сохранения `role=status`, форму закрыть только при успехе.
На время сохранения отключить submit и смену склада/представления, чтобы ответ
не обновил прежний контекст. При отмене формы не терять текст от фонового reload.

## Компоновка и tokens

Оболочка `max-w-7xl`, padding 16px mobile / 24px desktop, вертикальные интервалы
16–24px; заголовок 24px bold, секция 18px semibold, основной текст 14–16px.
Формы: одна колонка <640px, две ≥640px; длинные строки SKU/причин занимают всю
ширину. При 360px все кнопки доступны, min-height 44px, подписи переносятся.
Данные на mobile — семантические article + dl, desktop — таблица с caption и
scope=col, overflow только контейнера таблицы. `min-w-0`, `break-words` для
длинных номеров/названий/комментариев. Не делать всю строку единственной ссылкой.

Цвета как KPI: `bg-white dark:bg-slate-900`, основной
`text-slate-950 dark:text-slate-100`, вторичный
`text-slate-600 dark:text-slate-300`, границы
`border-slate-300 dark:border-slate-600`. Primary blue700/white и hover blue800;
не наследовать конфликтующий neutral hover. Ошибка rose800/rose200,
успех emerald800/emerald200, предупреждение amber900/amber200.
Цель WCAG AA: текст >=4.5:1, фокус/controls >=3:1; статус всегда текстом.

## Состояния и доступность

- Loading с локализованным текстом и `aria-busy`, empty только после ответа.
- Различать «Нет записей», «По фильтрам ничего не найдено», «Нет доступных складов».
- Network error с retry; 403 очищает старые данные/действия, 409 обновляет
  актуальный документ и сохраняет ввод для исправления.
- Защита stale response при смене склада/фильтров; не сохранять старые actions.
- Видимый focus-visible outline 2px с offset. Нативные buttons/selects.
- Открытие деталей фокусирует h2 tabindex=-1; закрытие возвращает фокус на
  вызвавшую кнопку (либо устойчивый заголовок списка, если строка исчезла).
- Нет необходимости modal для длинных форм. Если используется dialog,
  обязательны trap/Escape/возврат фокуса существующего AccessibleDialog.
- Не делать весь список live region; объявлять результат действия один раз.

## Локализация

Явные словари RU/KY/zh-Hans/zh-Hant для всех labels, статусов, ошибок,
пустых состояний, aria-текстов, типов движений и документов. Traditional Chinese
не копировать из simplified. Бизнес-названия RU/KY/ZH с fallback на непустое
исходное; даты и числа через Intl выбранной локали. JSON codes не выводить
единственным пользовательским сообщением. Отсутствие cost field не считать нулём.

## Файлы и приёмка

Frontend: новый `components/WarehouseView.tsx`, `lib/warehouse-i18n.ts`,
warehouse DTO в `types/index.ts`, API методы в `lib/api.ts`, интеграция
`Navbar.tsx`/`app/page.tsx`. Общие tokens/зависимости менять только согласованно.
Конкретные поля и действия финализируются по `docs/api/warehouse.md` от Backend;
несоответствие API не обходить на клиенте.

1. Пользователь видит только назначенные склады и не получает cost без права.
2. Черновик приёмки создаётся, проверяется и проводится отдельно; после reload
   статус/движение сохраняются, нет прямого редактирования остатка.
3. Инвентаризационный факт не меняет остатки до отдельного утверждения;
   устаревший пересчёт даёт понятный конфликт.
4. Движение показывает первичный документ, доступный источник открывается.
5. Все новые строки переведены на четыре языка; формы работают в обеих темах,
   keyboard-only, 360px/mobile/tablet/desktop.
6. Проверены loading/empty/network/403/409/retry и сохранение ввода.
7. Отчёт исполнителя разделяет lint/tsc/build от реально выполненных browser,
   screen reader и контрастных проверок; весь Г.7 этим этапом не закрывается.
